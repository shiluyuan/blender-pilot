# Blender Copilot 对照与优化依据

调研日期：2026-10-24。对照仓库为 [XEonAX/blender-copilot](https://github.com/XEonAX/blender-copilot)，固定版本 [`ba38965c280005ef7162a1138346f3f5ad59224f`](https://github.com/XEonAX/blender-copilot/tree/ba38965c280005ef7162a1138346f3f5ad59224f)，提交日期 2026-09-26。以下基于实际源代码及本次运行的上游纯 Python 检查；没有把其演示录像当作本次复现结果。

## 值得采用的体验

| 设计                         | 上游实现证据                                                                                                                                                                                                                                                                                     | Blender Pilot 应采用的方式                                                                                               |
| ---------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------ |
| 每轮变化有回执，也有恢复入口 | [`undo.py`](https://github.com/XEonAX/blender-copilot/blob/ba38965c280005ef7162a1138346f3f5ad59224f/blender_copilot/undo.py) 的 `receipt()`；[`panel.py`](https://github.com/XEonAX/blender-copilot/blob/ba38965c280005ef7162a1138346f3f5ad59224f/blender_copilot/panel.py) 的 `_draw_receipt()` | 在对话内展示已有的有限变化回执与操作前快照，直接进入恢复流程，减少用户寻找快照页面的成本。恢复前继续保存当前场景。       |
| 运行中能看懂正在做什么       | `panel.py` 的 `_draw_working()`；[`conversation.py`](https://github.com/XEonAX/blender-copilot/blob/ba38965c280005ef7162a1138346f3f5ad59224f/blender_copilot/conversation.py) 的 `elapsed()`、`busy_note()`                                                                                      | 区分等待模型、接收回复、执行工具、检查结果与正在停止；耗时由实际时间计算，不伪造完成百分比。                             |
| 工具循环有明确边界           | `conversation.py` 的 `_cap_reason()`、`_run_call()`、`_flush_pending()`                                                                                                                                                                                                                          | 保留我们的工具/截图/最终修正预算，增加重复失败检测；达到预算要结束任务并说明原因，不能只向模型反复返回同一错误。         |
| 中止后历史仍可继续           | `conversation.py` 的 `cancel()` 为尚未运行的调用补充 cancelled 回执；[`transport.py`](https://github.com/XEonAX/blender-copilot/blob/ba38965c280005ef7162a1138346f3f5ad59224f/blender_copilot/transport.py) 过滤旧进程事件并在取消宽限期后终止 worker                                            | 我们继续由 Codex 原生协议处理模型历史，应用保存单调事件游标与最终回执；取消后可继续会话，不自动重放不确定的场景修改。    |
| 上下文裁剪可解释             | [`context.py`](https://github.com/XEonAX/blender-copilot/blob/ba38965c280005ef7162a1138346f3f5ad59224f/blender_copilot/context.py) 的 `plan()`、`validate_projection()`；`panel.py` 的上下文明细                                                                                                 | Codex 原生历史由内核维护；上传文档的正文预算、截断与遗漏继续通过 `attachment.context` 告知用户，不再维护第二份模型历史。 |

上游默认每轮 8 个模型轮次、24 次工具调用，同一调用第三次重复前停止，连续 3 轮全部工具失败也停止。这些数字来自 `conversation.py` 常量和运行前检查，不应照搬为我们所有场景的合适默认值。素材组合和自动视觉检查本身也消耗调用，应为它们预留预算。

## 产品差异与真实边界

| 维度         | Blender Copilot 此版本                                                                                                                                                                                                           | Blender Pilot 已有能力与边界                                                                                                                |
| ------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------- |
| 使用位置     | Blender 原生 N 面板；模型代码直接在当前 Blender 进程执行                                                                                                                                                                         | Web 工作台连接服务器上的真实 Blender 桌面，适合仅能通过 HTTP(S) 访问的部署。MCP 远程调用并不意味着维护第二份场景副本。                      |
| 聊天表现     | 原生 `UILayout`，工具折叠、错误和运行状态细致；正文为纯文本，完整历史另镜像到 Text 数据块                                                                                                                                        | 可滚动聊天、Markdown/GFM、代码复制、图片预览、按会话草稿、重连重放和幂等投递。                                                              |
| 视觉反馈     | [`prompt.py`](https://github.com/XEonAX/blender-copilot/blob/ba38965c280005ef7162a1138346f3f5ad59224f/blender_copilot/prompt.py) 明确告诉模型看不到视口/UI/渲染；工具表仅 `run_blender_python`、`get_scene_info`、`get_rna_info` | 操作前/后和最终检查的真实截图送入多模态模型，并绑定 captureId、场景版本及检查报告。截图检查不能证明完整拓扑或艺术质量。                     |
| 复用素材     | 在所检查的面板、工具表和状态模型中，未发现跨项目素材目录或模板中心                                                                                                                                                               | PostgreSQL 素材目录、分类/标签/收藏/搜索、外部文件上传、选中层级保存、预览、独立副本导入、来源与许可记录；复杂驱动/缓存的依赖闭包仍有边界。 |
| 多项目       | 历史按 `.blend` 路径区分，Save As 保留别名                                                                                                                                                                                       | 多项目标签、项目独立 Blender 实例与会话、共享素材库；当前没有多人协作编辑锁。                                                               |
| 恢复方式     | 目标是一轮一个 Ctrl+Z；`undo.py`、`undo_blender.py` 区分编辑模式、Global Undo 与覆盖边界                                                                                                                                         | 以 `.blend` 操作前/后快照恢复为主，恢复前再备份。我们没有承诺一轮一个 Ctrl+Z，也不能把文件、网络等外部效果称为可回滚。                      |
| 停止阻塞代码 | [`budget.py`](https://github.com/XEonAX/blender-copilot/blob/ba38965c280005ef7162a1138346f3f5ad59224f/blender_copilot/budget.py)：Python 调用 15 秒、每轮累计代码 60 秒；SIGALRM 不能保证抢占长时间 native 调用，也可被代码关闭  | 取消停止后续工具和模型轮次；已经进入 Blender 的阻塞脚本不保证立即中断。API 超时不等于场景已停止修改，不据此自动重试场景写入。               |
| 保存         | [`store.py`](https://github.com/XEonAX/blender-copilot/blob/ba38965c280005ef7162a1138346f3f5ad59224f/blender_copilot/store.py) 临时文件 + `os.replace`，JSON 历史按完整轮次裁剪                                                  | PostgreSQL 保存应用数据，本地保存内容文件，执行事件保留日志；磁盘异常时停止接收不确定写入，不静默报告成功。                                 |

不能据此宣布整体“更稳定”或“更快”：两者的运行环境、模型及交互范围不同，本次没有同模型、同机器、同任务的双方完整性能对照。我们的优势方向是服务器工作台、真实视觉闭环，以及可复用素材/模板；上游的原生上下文、每轮撤销和细致的边界提示也有实际价值。

## 本次实际探测

将固定版本的上游 Python 模块及 4 个测试脚本放入临时研究目录，分别使用 `python3 tests/<file>` 执行，所有脚本退出码均为 0。它们采用脚本级断言打印，不是 `unittest.TestCase` 套件；不能用 `unittest` 的测试计数描述它们。

| 上游脚本                        | 输出的通过断言行数 | 涵盖内容                                                                    |
| ------------------------------- | -----------------: | --------------------------------------------------------------------------- |
| `tests/test_context.py`         |                 87 | 上下文预算、工具调用/结果成对、投影不改写原历史、3,600 次生成式对话投影检查 |
| `tests/test_conversation.py`    |                456 | 对话状态机、工具队列、取消、调用预算、失败回执、运行指示与配置              |
| `tests/test_read_only_tools.py` |                110 | 场景查询、分页/截断、RNA 查询、缺失名称和参数错误                           |
| `tests/test_store.py`           |                 75 | 按文件隔离、Save As、按轮保留、损坏索引恢复、删除路径边界                   |

共 728 行通过断言；数量不能与本项目 Node 测试用例数直接比较。这次没有运行上游插件的 GUI、上游真实模型或它的飞船演示。上游 README 报告的速度、token、撤销和阻塞实验属于作者自己的记录。

本次查询的 GitHub Releases 返回空列表，唯一 issue 是演示视频托管。README 自称 prototype；不能从少量 issue 推断长期运行成熟度。README 的“48,000-byte budget”也不是当前代码全部预算配置的准确描述：`context.py` 已采用按窗口推导的预算，并提供 KiB 调节。对标实现应以固定版本代码和探测结果为准。

## 素材与模板的验收标准

新增能力应围绕可重复完成的用户任务，而不是增加入口数量：

1. 从模板选择一个明确的起点，能看懂生成目标、需要填写的参数及会修改什么；模板不是预先生成的高精度模型承诺。
2. 把人物、物品、场景或材质样例加入共享素材库，能查找、预览、引用，并追加到不同项目；编辑副本不改变原件。
3. 用若干库素材与新对象组合后再次保存，保留直接素材来源关系，在其他项目仍能复用。
4. 任务预算或连续失败触发停止时，对话给出明确原因、已发生的变化及操作前备份入口；不把停止显示成成功。
5. 失败重试、刷新与会话切换继续沿用幂等请求/事件协议。模板或素材引用不能绕开会话归属、附件校验和场景队列。

## 本轮已落地

- `TemplatesPanel`、`TemplateCatalog` 与迁移 v2：6 类内置配方、自定义模板、参数预览、素材绑定、版本冲突和跨项目使用。模板只是准备草稿，用户发送后仍走原有 Codex/MCP 协议。
- 对话时间线展示 `snapshot.created`，直接下载或恢复；工具卡片显示实际耗时与 `scene.receipt` 摘要，失败时保留已发生变化。
- MCP 初始化与关闭竞态的进程清理；任务取消/日志失败后的 token 回收；相同失败调用限制，以及 40 次工具预算触发整轮中断。
- 模板合并使用最新会话记录，保留异步完成的附件；正文与附件上限统一，素材本地文件缺失在调用模型前拒绝。

本轮实际测试及截图见 [验收记录](validation.md)；上游测试数量与我们的测试用例数量不作横向评分。
