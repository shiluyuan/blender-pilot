# 创作阶段与质量检查

新对话默认使用多角度验收：执行结束后，系统取得三个方向的真实画面与当前结构报告，再要求模型报告观察结果。工具调用成功或模型口头说“完成”都不足以使任务显示检查通过。

## 复杂任务按阶段进行

Codex 的指令要求复杂场景先调用 `update_work_plan`。计划最多八个阶段，同一时间只有一个进行中的阶段，可记录布局、复用素材、几何体、材质灯光和验收等步骤。每个阶段记录状态、实际对象名称和备注。

标记新阶段完成时，服务器验证对象确实存在，并创建一个 Blender 恢复点。计划与恢复点通过已有任务事件协议持久化，浏览器刷新后可重放显示。下一轮会提供同一对话最近的计划作为上下文，模型先读取当前场景，再按用户要求继续或只调整指定部件。

这是受模型执行的分阶段工作流：不是自动重试队列，也不保证每条自然语言需求都被完美拆解。服务重启不会重放 Blender 写操作；未完成或受阻阶段不会自动改成完成。用户可继续对话或使用快照恢复。

## 结构与画面分别检查

`inspect_scene_quality` 读取有界的对象、包围盒、网格、材质和缺失贴图等信息。无效变换等结构错误会阻止通过；空网格等提醒需要结合对象用途判断。悬空和相交提示基于包围盒等近似条件，可能是设计中合理的情况，需要模型结合画面解释，不能视为精确碰撞检测。

`capture_views` 取得不同方向的实际画面，默认正面、右侧、俯视。截图保留当前项目、任务、版本与生成代次信息，不创建场景相机或修改用户模型。渲染画面可能触发 Blender 的变更计数，因此先取得多角度画面，再读取结构报告。

系统校验 `report_verification` 引用当前完整的三张截图和结构报告。场景变化、结构错误、过期检查或未完成的创作阶段都不能通过。更新计划、重新检查或重新获取画面会使旧的通过结论失效，保存最终结果前还会再次校验。修正有次数与工具预算上限，耗尽后如实显示需要检查。

多角度视口检查覆盖可见轮廓、摆放和材质线索，不能替代最终渲染、完整拓扑检测、精确穿模检测或艺术审美。结构检查有对象数和候选对数上限，报告会标出截断范围；没有自动“好看评分”。需要灯光或最终材质效果时，应在对话中明确要求相应渲染并检查结果。

## 对话中的结果与状态

- 等待时显示准备场景、等待模型、操作 Blender、检查画面或保存结果等真实阶段。
- 本轮结果展示对象新增／修改／移除、操作前后画面、结构提醒、是否保存到 `scene.blend` 及未完成阶段。
- 可打开原图、下载恢复点，或恢复到操作前。前后画面可能采用不同观察方向，不是像素对齐的差异图。
- 变更摘要覆盖名称、变换、尺寸、材质关联和顶点数，不能声称覆盖所有拓扑、节点或动画变化。

## 参数化模板

模板中心在原有六个配方上增加书桌、置物架和办公室布局。参数支持文本或数值，数值可声明单位、上下限和步长；例如桌面宽度以米计、柜体层数只接受整数。

编辑器、预览和后端使用同一套校验。模板中的数值生成明确的建模指令；它们不是绑定到现有网格的自动参数修改器。实际生成尺寸仍应由 Blender 回读与质量检查确认。已有文本参数及自定义模板保持兼容。
