# 上线前验收

当前适合在自己的服务器上进行受控试运行。正式生产发布仍需在实际部署主机完成 Docker 镜像启动和原生 PostgreSQL 验收。本云端没有 Docker daemon，不能把原生进程测试或 PostgreSQL WASM/TCP 检查称为容器部署验收。

本轮真实 Key 的核心 5 个任务（4 成功、1 预期取消）和独立的模板组合重测通过。原完整运行的组合任务超过测试脚本原定 4 分钟等待上限，清理过程将其打断；该尝试没有记作通过。等待策略已改为覆盖 Codex 15 分钟 turn 与收尾，并在新项目中完成组合重测。

最后的真实模型浏览器阶段被自动审批中断，没有生成完整通过报告。审批理由是缺少向 `https://coding.smartpaipai.com` 发送本地场景/截图的特定目的地确认。已核对该验收只使用默认几何体、脚本生成的素材和测试提示，没有使用用户上传的实际场景。该项标记为受阻，待确认后补测，不计作通过。

机器证据见 [本轮汇总](validation/release-readiness-2026-10-24.json)、[双 Blender 原生场景](validation/release-workspaces-2026-10-24.json)、[真实模型核心](validation/release-core-model-2026-10-24.json)、[组合重测](validation/release-template-model-2026-10-24.json)、[受阻记录](validation/release-live-blocked-2026-10-24.json) 和 [固定镜像标签检查](validation/release-image-manifests-2026-10-24.json)。镜像标签检查只读取了官方 Registry manifest，没有运行镜像。

## 本轮场景

| 用户场景 / 故障                | 本轮验证                                                          |
| ------------------------------ | ----------------------------------------------------------------- |
| 首次使用、密码错误、模型未配置 | 明确提示，要求和附件保留，配置后可继续                            |
| 项目与会话切换                 | 两个项目交替切换六次，草稿、文档和引用归属独立                    |
| 发送中登录过期                 | 重新登录后保留消息编号与附件，继续核对接收回执                    |
| 服务已接收但客户端没收到回执   | 不释放项目占用，不重复创建任务，不让新任务越过未确认操作          |
| 网关重启、迟到任务             | 先持久化取消标记，再结束丢失任务；迟到提交不会继续操作场景        |
| 某个项目状态请求挂起           | 最多三路同步，状态/事件查询限时五秒；其他项目仍能完成             |
| 活动任务取消与迟到状态竞争     | 取消意图保持，不被迟到的 running 状态覆盖                         |
| 图片或截图文件丢失             | 在任务接收前报错，保留用户输入                                    |
| 上传中登录过期                 | 重新登录后恢复分片，附件不重复                                    |
| 退出登录与过期连接             | 撤销单个登录；已有 SSE/桌面连接关闭，旧 Cookie 不能重放           |
| 40 轮历史刷新                  | 任务与工具卡片完整，无重复；上翻意图不被新消息覆盖                |
| 双 Blender 并行                | 场景、原生 Codex 会话和任务独立；实例容量上限明确拒绝             |
| 素材与组合                     | 外部 GLB 贴图、独立副本、组合入库、来源关系与跨项目复用           |
| Blender 进程崩溃               | 故障按项目报告，另一项目继续工作，重新打开恢复已保存场景          |
| 网关与 Runner 故障             | 回执持久化、任务标记中断、不自动重放；完成记录保留                |
| 部署参数与检查                 | IPv6 地址、缺失 Key、错误模型 URL、活动任务保护、显式测试实例开关 |

自动检查覆盖 72 项 Node 应用/协议/SQL/故障用例和 11 项 Python 部署用例。浏览器覆盖 15 项聊天、20 项模板及 9 项新增旅程，均使用真实 Fastify、pg/TCP 和 Chromium；受控的 Runner/模型响应有明确夹具标识。双 Blender 的 12 组测试操作真实场景和真实原生 Codex 协议，模型返回受控响应，适合验证并行、故障与恢复。

故障注入中的 Runner 测试实际终止的是本次测试的 Runner Node 进程。此云端无法枚举该进程的子进程，报告记录 `runnerChildrenEnumerated: 0`；不将其描述为 Docker 容器重启。另一个 Blender 进程故障由已知 Blender PID 单独注入。

## 已修复的问题

- 接收回执不确定时过早释放项目占用，以及网关重启后的迟到提交。
- 项目间事件/资源归属校验、缺失文件提前校验与状态请求挂起隔离。
- 登录过期后缺少恢复入口、同一会话重新登录后未重新加载历史/回执、迟到 401 打断新登录。
- 退出后旧 Cookie 和长期连接继续有效；现在以数据库令牌哈希记录撤销，vault 与模型 Key 不变。
- 排队的程序化滚动覆盖用户上翻意图；回归包含确定性的竞态事件顺序。
- IPv6 端口与探测地址、模型参数的部署前校验、部署测试意外切换正常实例模型配置。

升级到认证迁移 v3 时，旧 Cookie 需要重新登录一次。项目、素材、原生模型会话、vault 和已保存模型配置保留。

## 实际部署后的验收

```bash
./docker-up.sh
# 在网页配置模型后执行基础服务检查；宿主机无需 Node。
docker compose --env-file .env exec -T web \
  node dist/server/apps/server/readiness.js
```

健康检查使用独立临时登录，结束时只退出该登录。它检查服务、数据库、执行端、故障实例、空间和模型配置，不改变业务场景或模型配置。真实模型的图片理解、工具调用、截图报告与导出仍以真实任务验收为准。

`PILOT_TEST_DISPOSABLE=1 npm run test:e2e` 仅用于可丢弃测试部署，会改写模型配置并创建场景。普通实例使用上面的健康检查。详细参数与备份方法见 [部署运维](deployment.md)。
