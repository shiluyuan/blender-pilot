# PostgreSQL 与文件存储

生产环境仅使用 `pg` 驱动连接 PostgreSQL，不会回退到 PGlite、SQLite 或 JSON 数据库。默认部署固定 `postgres:18.6-bookworm`，也可指定已有 PostgreSQL。应用要求 PostgreSQL 16 或以上，连接角色需有目标 schema 的建表权限；首期一个 Web 实例，暂不宣称可水平扩容多个网关进程。

## 表设计

| 表                                     | 作用与约束                                                                                                                    |
| -------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------- |
| `schema_migrations`                    | 已应用的版本和时间；事务级 advisory lock 避免启动时重复迁移                                                                   |
| `projects`                             | 名称、创建/修改时间、完整项目实体                                                                                             |
| `sessions`                             | 项目外键、标题、原生 thread ID；项目/时间索引                                                                                 |
| `runs`                                 | 项目、会话、状态、验证状态和时间；复合外键确保会话属于同一项目；部分唯一索引确保每项目最多一个 queued/running/cancelling 任务 |
| `requests`                             | 请求幂等键及 run 外键；与任务创建在同一事务提交                                                                               |
| `events`                               | `(run_id, seq)` 主键、事件类型与版本化 JSONB 内容；重复同步不会产生重复事件                                                   |
| `assets`                               | 项目外键、名称、类型、文件路径、SHA256、大小；项目/时间与项目/哈希索引                                                        |
| `captures` / `snapshots` / `artifacts` | 项目归属和创建时间；完整文件元数据                                                                                            |
| `uploads`                              | 可空项目归属，保存目的地、实际偏移、完成状态等恢复信息                                                                        |
| `library_assets`                       | 名称、分类、标签数组、收藏、源项目、路径、哈希、大小与创建时间；分类/时间、收藏和 GIN 标签索引                                |
| `library_asset_sources`                | 组合素材到源素材的关系；双方外键、禁止自引用与重复关系                                                                        |
| `config`                               | 模型配置、加密 Key 与工作台状态；密钥不以明文入库                                                                             |
| `migration_imports`                    | 旧数据导入完成标记和数量记录                                                                                                  |

实体同时保留 JSONB API 数据，便于事件版本兼容与逐步扩展；所有权、任务状态、检索字段与时间使用独立类型列。代码在 `packages/storage/schema.ts`、`apps/server/db.ts` 与 `packages/storage/library-catalog.ts`。所有 SQL 表名限定 schema，参数值使用占位符。

素材列表、分类和收藏从 PostgreSQL 查询，不扫描目录作为在线数据库。中文名称/描述采用子串查询；标签有 GIN 索引，当前没有承诺数十万素材的全文检索性能。

## 事务与故障恢复

- 请求创建先取得幂等键事务锁，再原子写入任务和请求映射。数据库约束阻止同项目产生两个活动任务。
- 事件和由其生成的截图/快照/导出记录在同一事务同步，避免事件已确认而附件记录丢失。
- 项目上传在完成元数据事务前保留原始分块文件。失败可重试，不需要重新上传。共享素材上传使用上传 ID 作为稳定素材 ID；库条目已提交而上传完成标记失败时，重试会修复标记。
- 素材元数据更新锁定单行再合并，避免收藏操作覆盖其他字段。内容文件不可变，写完后才发布数据库条目；正常失败清理未发布目录。
- 数据库连接池处理空闲连接错误；`/api/ready` 返回真实数据库可用性。服务不因数据库暂时不可用而建立一个空的替代数据库。

Runner 的 NDJSON、任务状态和 Codex 原生会话是本地恢复日志；对话/任务的在线查询和素材目录由 PostgreSQL 提供。文件系统与数据库之间不是分布式事务，主机断电和整盘损坏仍需要备份；未发布的孤立目录不会出现在素材库中。

## 旧数据迁移

`docker-up.sh` 发现 `<data-dir>/database/PG_VERSION` 或 `library/*/asset.json` 后，停止 Web/Studio，再使用应用镜像执行离线迁移：

```bash
docker compose --env-file .env --profile bundled-db run --rm --no-deps web \
  node dist/server/apps/server/migrate.js
```

迁移会复制旧 PGlite 目录到暂存区读取，原库保持原样。项目、会话、任务、上传和配置按依赖顺序导入，事件、幂等键、素材元数据及来源关系一起提交。旧活动任务标记 interrupted，避免重复执行 Blender 写入；加密配置字节不改动，必须保留 `config/vault.key`。

目标 schema 已有业务数据时拒绝覆盖；导入成功后写入完成标记，重跑会跳过。错误会回滚，原文件仍在，修复后可重试。旧数据路径需在容器内仍对应 `/data`。一键脚本会把默认旧命名卷 `blender-pilot_pilot-data` 复制到空的本地数据目录，复制前停服务，原卷只读保留；自定义旧卷可通过 `--legacy-volume` 指定。目标目录已非空时不覆盖。不要只移动 `.blend`。

升级前另做备份。迁移依赖保留在镜像中，仅供离线导入，不作为生产数据库后端。

## 备份

数据库与 `--data-dir` 必须一起保存。推荐停止 Web/Studio 后 `pg_dump -Fc`，再归档本地文件目录，完成后重新启动。PostgreSQL 原始目录的冷备应在数据库也停止后执行。恢复到另一个主机时保持应用内路径 `/data` 与 uid/gid 1000，并保留 vault 主密钥。
